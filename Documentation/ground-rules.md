# Ground Rules

## Important Context Guidelines

Before we get started, I want to lay down some extremely important ground rules. **Please do not ever let these slip out of your context window:**

## Core Principles

### 1. Precision and Accuracy
When it comes to anything touching the codebase, **precision and accuracy is extremely important**. 
- **Use your tools, don't guess**
- If you're unsure about code or files, **open them**
- If you're not absolutely sure you have the latest version or ask me for the latest version – **do not hallucinate or approximate**

### 2. Planning and Reflection
I want you to **plan and reflect on every code ask** I have. 
- **Avoid trial and error**
- Think through the approach before implementing
- Consider potential impacts and side effects

### 3. Persistence
**Keep going until the job is completely solved** before ending your turn.
- Don't leave tasks partially completed
- Follow through on all aspects of a request
- Ensure everything works as expected

## Perfect Format for Code Changes

Below is the perfect format for code changes. The code being referenced is **100% accurate** to my latest code and the instructions are **crystal clear**. The follow-up of "After your change, lines x-y should read:" gives me confidence that the change I made is the correct one. 

**Let's always use this format when making code changes.**

### Code Change Template

```
Target File: [file path]
Current Code (lines x-y):
[exact current code]

Proposed Change:
[clear description of what needs to change]

New Code (lines x-y):
[exact new code]

After your change, lines x-y should read:
[verification of the expected result]
```
